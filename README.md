# 파이낙사 온리전 :: 사랑의 진도

---

## 프로젝트 개요

사랑의 진도는 아마추어 창작 교류 행사 운영을 위한 웹 애플리케이션입니다. 방문자가 행사 소개와 공지, 참가 부스 정보를 확인하고, 행사 주최자는 관리자 화면에서 콘텐츠와 문의를 관리할 수 있도록 개발했습니다.

클라이언트가 제공한 기획과 디자인을 바탕으로 프론트엔드·백엔드 구현과 데이터베이스 구성, 배포를 단독으로 담당했습니다.

- 개발 형태: Spring Boot 기반 웹 애플리케이션
- 개발 인원: 1인
- 개발 기간: 20일
- 기획·디자인: 클라이언트 제공
- 배포 이력: 가비아 컨테이너 호스팅
- 운영 상태: 현재 배포 중단

## 구조 및 설계

### 전체 구조

Spring MVC를 기반으로 Controller, Service, MyBatis Mapper 계층을 구성했습니다. SQL은 Mapper XML에서 관리하고, 조회 결과와 요청 데이터는 DTO로 전달했습니다.

행사 소개와 메인 화면은 Controller에서 Model에 데이터를 담아 Thymeleaf로 렌더링했습니다. 게시글 목록, 부스 필터링, Q&A와 관리자 화면의 일부 작업은 REST API와 Fetch API로 처리했습니다.

### 사용자 역할과 관리자 영역

회원 역할은 일반 회원인 `USER`, 부스 회원인 `BOOTH`, 관리자인 `ADMIN`으로 구분했습니다. Spring Security에서 관리자 화면과 API, 행사 소개 수정 화면, 부스 회원 게시판 등의 접근 규칙을 설정했습니다.

공통 로그인 정보는 `@ControllerAdvice`에서 Model에 전달했습니다. 이를 이용해 헤더 메뉴와 작성·수정 버튼 등 화면 요소를 로그인 상태와 역할에 따라 분기했습니다.

### 공통 UI와 모바일 레이아웃

헤더·푸터·관리자 내비게이션·토스트는 Thymeleaf fragment로 분리했습니다.

일반 사용자 페이지에는 모바일 레이아웃을 적용했습니다. 화면 너비가 768px 이하일 때 헤더를 햄버거 메뉴로 전환하고, 메인 공지 메뉴와 부스 목록 등의 배치를 변경했습니다. 관리자 화면은 데스크톱 기준으로 구성했습니다.

## 주요 기능

- 행사 안내: 슬라이드 배너, 주요 공지 링크, 행사 소개
- 회원 관리: 회원가입, 로그인·로그아웃, 아이디 저장, 비밀번호 변경
- 게시판: INFORMATION·EVENT·부스 회원 게시판, 공지 고정, 게시글 작성·수정·삭제
- 댓글: 부스 게시판의 댓글 작성·수정·삭제 UI
- 부스 정보: 참가자·SNS 링크 조회, 태그 조합 필터링
- Q&A: 회원·비회원 질문 작성, 내 질문 필터, 비밀번호 확인 UI
- 관리자: 배너·링크·공지·부스·질문 관리, 답변 작성, 부스 계정 전환 및 비밀번호 초기화

## 구현

### 메인 페이지와 행사 소개

메인 배너의 이미지·배경색·이동 URL과 공지 메뉴의 연결 주소를 데이터베이스에서 조회해 Thymeleaf로 표시했습니다. 관리자 화면에서 해당 값을 수정하고 초기화할 수 있도록 구성했습니다.

배너는 JavaScript로 직접 제어했습니다. 좌우 버튼과 도트 선택, 3초 간격의 자동 전환을 구현하고, 현재 배너에 맞춰 배경색과 선택 표시를 함께 변경했습니다.

행사 소개는 Quill 에디터로 편집하도록 구성했습니다. 저장된 본문을 에디터에 불러오고, 수정한 HTML을 폼으로 전송해 데이터베이스에 반영했습니다. 수정 화면과 저장 요청에는 관리자 접근 규칙을 적용했습니다.

### 회원가입과 로그인

Spring Security의 폼 로그인과 `CustomUserDetailsService`를 이용해 데이터베이스의 회원 정보로 인증하도록 구성했습니다. 회원 역할은 Spring Security 권한으로 변환하고, 로그아웃 시 세션을 무효화하도록 설정했습니다.

회원가입 화면에서는 아이디 형식과 중복 여부, 비밀번호 규칙과 확인 입력을 검사했습니다. 회원가입과 비밀번호 변경 시에는 BCrypt로 해싱한 값을 저장했습니다.

아이디 저장 기능은 `localStorage`를 사용해 로그인 폼의 입력값을 저장하고 복원하는 방식으로 구현했습니다.

비밀번호 복구는 관리자가 초기화하는 방식으로 구성했습니다. 관리자 화면에서 대상 회원의 비밀번호를 지정된 초기값의 BCrypt 해시로 변경할 수 있도록 했습니다.

### 공통 게시판과 댓글

INFORMATION·EVENT·부스 회원 게시판은 게시판 유형을 구분하는 공통 Controller·Service·Mapper와 템플릿으로 처리했습니다.

목록 화면의 공지글은 Model로 전달하고, 일반 게시글은 API에서 조회했습니다. 조회한 목록은 브라우저에서 열 개씩 나누어 표시했습니다. 관리자 작성 글은 작성자 표시를 행사 내 명칭인 ‘교무처장’으로 변경했습니다.

게시글 작성·수정에는 Quill 에디터를 적용했습니다. 이미지 업로드 결과를 본문에 삽입하고, 수정 시 기존 내용을 에디터에 복원했습니다. 제목과 본문이 비어 있으면 제출을 막도록 구성했습니다.

게시글 수정은 화면 진입과 실제 수정 요청에서 작성자 여부를 확인했습니다. 삭제는 관리자만 처리하도록 구현했습니다. 비밀글 상세 화면에서는 작성자 또는 관리자 여부를 검사하고, 같은 게시판의 이전·다음 글 이동도 제공했습니다.

댓글 UI는 부스 게시판에 표시했습니다. 등록 후 목록과 댓글 수를 다시 조회하고, 수정 성공 시 내용을 갱신하며, 삭제 전에는 확인 모달을 표시하도록 구성했습니다.

### 부스 정보와 태그 필터링

부스 목록은 REST API에서 조회해 이미지, 부스명, 참가자, 태그를 표시했습니다. 참가자 이름에는 등록된 SNS 주소를 연결하고, 마우스를 올리면 부스 이미지가 교체되도록 구현했습니다.

일반·성인 구분은 하나만 선택하고, 창작물 유형 등의 태그는 여러 개를 선택하도록 구성했습니다. 선택한 태그는 반복 쿼리 파라미터로 서버에 전달했습니다.

데이터베이스에서는 부스와 태그를 매핑 테이블로 연결했습니다. 필터 조회에는 `GROUP BY`와 `HAVING COUNT(DISTINCT ...)`를 사용해 선택한 태그를 모두 포함한 부스를 반환하도록 구현했습니다.

관리자 화면에서는 등록 폼을 수정 폼으로 전환해 재사용했습니다. 부스 정보와 태그 매핑의 등록·수정은 트랜잭션으로 묶고, 수정 시 기존 태그 매핑을 갱신하도록 구성했습니다.

### 회원·비회원 Q&A

회원과 비회원 모두 질문을 등록할 수 있도록 구현했습니다. 로그인한 회원의 작성자 ID는 서버 인증 정보에서 가져와 저장했습니다.

질문 목록은 API로 조회한 뒤 브라우저에서 열 개씩 나누어 표시했습니다. 로그인한 사용자는 자신의 ID를 기준으로 작성한 질문만 필터링할 수 있도록 구성했습니다.

비밀글은 로그인 상태와 작성자 여부에 따라 표시 UI를 분기했습니다. 비회원 질문에는 비밀번호 설정과 확인 흐름을 연결하고, 질문 비밀번호는 BCrypt로 해싱해 저장했습니다. 비밀번호 확인에 성공하면 본문과 답변을 표시하도록 구성했습니다.

관리자 화면에서는 질문을 선택하면 해당 내용을 답변 폼에 채우고, 답변 등록·수정과 질문 삭제를 처리했습니다. 비밀글의 서버 응답 범위에는 보완이 필요한 부분이 남아 있습니다.

### 이미지 업로드와 배포

Quill 본문과 배너·부스 이미지에 사용할 공통 업로드 API를 구현했습니다. 파일명은 UUID로 생성하고, 서버의 카테고리별 디렉터리에 저장한 뒤 접근 URL을 반환했습니다.

일반 이미지는 너비가 기준을 초과하면 Thumbnailator로 비율을 유지하며 축소했습니다. GIF는 원본을 유지하도록 처리했습니다. 저장한 이미지는 `/uploads/**` 리소스 경로로 제공했습니다.

가비아 컨테이너 호스팅에 애플리케이션을 배포하고, FileZilla를 이용해 운영 파일을 반영했습니다. 행사 소개와 배너·공지·부스 정보 등 운영 중 변경되는 콘텐츠는 관리자 화면에서 관리하도록 구성했습니다.

## 기술적 고민 및 개선점

### 서버 권한 검증과 응답 데이터 범위

화면에서 버튼이나 내용을 숨기는 처리와 서버의 접근 제한을 구분해야 한다는 점을 확인했습니다. 일부 댓글 작업에는 작성자 검증이 부족하고, 게시판 API의 URL 표기와 Security 접근 규칙도 일관되게 정리할 필요가 있습니다.

Q&A는 비밀글 표시와 비밀번호 확인 흐름을 구현했지만, 목록 API가 본문·답변·비밀번호 해시를 함께 반환하는 한계가 있습니다. 공개 목록과 상세 응답을 분리하고, 상세 요청에서 작성자·관리자 권한 또는 비회원 비밀번호를 검증하도록 개선할 필요가 있습니다.

Quill HTML을 저장하고 출력하는 경로에도 서버에서 허용할 태그와 속성을 검증하는 처리를 보완하고자 합니다.

### 서버 기반 페이지네이션

게시글과 질문 목록은 전체 데이터를 조회한 뒤 브라우저에서 페이지를 나누는 방식으로 구현했습니다. 페이지 이동은 가능하지만, 화면에 표시하지 않는 과거 데이터도 처음부터 전송하는 한계가 있습니다.

이후에는 목록 조회 쿼리에 `LIMIT`과 `OFFSET`을 적용하고, 전체 개수를 별도로 반환해 필요한 범위만 조회하도록 개선하고자 합니다.

### 이미지 저장과 운영 파일 관리

이미지를 호스팅 서버 디렉터리에 저장하면서 파일 경로와 배포 환경이 연결됐습니다. 서버를 이전할 때 데이터베이스뿐 아니라 업로드 파일도 함께 옮겨야 하며, 이미지 교체·삭제 이후의 파일 정리도 보완할 필요가 있습니다.

후속 개선에서는 업로드 경로 설정을 통합하고 파일 정리·백업 기준을 마련하고자 합니다. 외부 스토리지 도입도 검토해 애플리케이션 배포와 이미지 보관을 분리할 수 있습니다.

### 공통 스타일 정리

페이지별 HTML과 CSS를 나누어 작업하면서 공통 레이아웃과 버튼·입력 요소의 스타일이 중복됐습니다. 공통 fragment를 사용하더라도 CSS까지 일관되게 관리하지 않으면 수정 범위가 커진다는 점을 경험했습니다.

이후에는 공통 스타일과 페이지별 스타일의 역할을 정리하고, 반복되는 UI의 크기·간격·상태 표현을 공통 규칙으로 관리하고자 합니다.
